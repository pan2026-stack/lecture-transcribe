# 课堂实时转写

上课打开网页，点「开始听课」，说话内容几秒后变成字幕；可以同时出中英对照；下课后点「生成笔记」，DeepSeek 把整节课整理成一篇完整讲稿加一份结构化笔记，存进 Obsidian 收件箱。

纯 Python 标准库，不用装任何依赖。

## 界面

顶部是状态，「开始听课 / 结束并保存」在右上；标题下面一行是 `● 正在听课 · 已转写 24 段 · 时长 12:34`，时长按真实录音秒数算（暂停不计入），结束后停住不动。

转写记录里每段一行时间码加原文，译文用灰字跟在下面。转写记录右上角有 `原文 / 中→英 / 英→中` 三档翻译开关，还有电平条、自动跟随、复制、生成笔记。

纸面配色跟随系统，浅色是暖白纸面加墨黑字，深色是纯黑加浅字；朱红只出现在「正在录音」和电平上。

## 启动

**双击桌面上的 `课堂转写.bat`** —— 会自动起服务并打开浏览器。

那个黑窗口就是服务本身，**关掉窗口即停止**；再双击时会发现服务已在运行，只打开网页，不会起第二份。

其他方式：双击本目录的 `启动.bat`，或者：

```powershell
cd "D:\课堂转写"
python server.py
```

浏览器打开 http://127.0.0.1:8787

> 必须用 `127.0.0.1` 或 `localhost` 打开，浏览器才允许用麦克风（换成局域网 IP 会被拦）。
> 推荐 Chrome / Edge。

## 两件事、两个 KEY

流程是「语音识别 → 整理笔记」，DeepSeek **只做后一半**（它没有音频接口）。

点右上角「设置」，填两组：

**① 识别（语音转文字）**

| 字段 | 示例 |
|---|---|
| base_url | `https://api.siliconflow.cn/v1` |
| model | `Qwen/Qwen3-ASR-1.7B` |
| API Key | 硅基流动的 `sk-...` |

**② 笔记生成（DeepSeek）**

| 字段 | 值 |
|---|---|
| 接口地址 | `https://api.deepseek.com` |
| 模型 | `deepseek-flash` |
| API Key | DeepSeek 的 `sk-...` |

也可以换别家识别服务，只要兼容 OpenAI 的 `/audio/transcriptions`：

| 服务商 | base_url | model |
|---|---|---|
| 硅基流动（默认，中文课堂最好） | `https://api.siliconflow.cn/v1` | `Qwen/Qwen3-ASR-1.7B` |
| 硅基流动（轻量、最快） | `https://api.siliconflow.cn/v1` | `FunAudioLLM/SenseVoiceSmall` |
| 硅基流动（商用级） | `https://api.siliconflow.cn/v1` | `XingChenAGI/XingChenASR-V3.2-Ultra` |
| OpenAI | `https://api.openai.com/v1` | `whisper-1` |
| Groq | `https://api.groq.com/openai/v1` | `whisper-large-v3-turbo` |

两个 KEY 都只存在本地 `config.json`，由本机服务端转发，不进浏览器、不上传别处。


## 参数

- **每段秒数**（默认 6）：现在是**单句最长时长**——检测到 320ms 停顿就提前断句，不再硬切；只有连续说话超过这个长度才强制切。
- **断句**：静音阈值 0.012、停顿 320ms、最短句 1.2s，写在 pp.js 顶部，可以调。
- **语言**：`zh` / `en` / 留空自动。
- **识别提示词**：把课程里的专有名词写进去，能明显改善同音错字。

## 识别跟不上时怎么办

原则是**先保证收全**：音频能救回来，字可以慢慢补。

1. **实时优先**：正常情况每 6 秒一段，边听边出字。
2. **自动降级**：排队积压到 8 段，或连续失败 3 次，自动切成「先存盘」——每段音频直接写进 `sessions/_audio/<会话号>/`，界面标签变成 `先存盘 · 待补识别`，横幅会说明原因。讲课照常继续，一个字都不丢。
3. **结束时自动补**：点「结束并保存」后，会把存盘的片段逐段送去识别（进度显示 `补识别 3/17`），转完再存稿。
4. **随时手动补**：录制中也可以点「补识别 N 段」。
5. **转成功即删音频**：`/api/transcribe-file` 识别成功立刻删除对应的 wav 和空目录，不长期占盘。
6. **失败的不丢**：没转成功的片段留在 `sessions/_audio/`，下次启动时清掉 3 天前的残留。

## 结束时自动出两份文档

点「结束并保存」不是只存稿，它会一口气做完：

```
补识别（如有降级）→ 存转写稿 → DeepSeek 整理 → 弹出结果 → 写进 Obsidian 收件箱
```

产出两份：

1. **完整讲稿**（`课堂原文-…md`）——去掉「嗯、那个、就是说」，合并重复和回补，按逻辑重排成通顺的书面文本，保留老师原话和例子。
2. **结构化笔记**（`课堂笔记-…md`）——主题一句 → 章节 → 重点提示 → 课后任务 → 自测题；开头有 `[[课堂原文-…]]` 双链指回讲稿。

关键概念**在正文里就地挂链接**，不另设「延伸阅读」节：`**二叉搜索树**（[维基百科](https://zh.wikipedia.org/wiki/二叉搜索树)）`。同一概念只挂第一次出现处，全篇上限由 `config.json` 的 `reading_list_max` 控制（默认 4）。只挂确定存在的来源（官方文档、标准、维基、出版社页、RFC、项目主页），拿不准就只写书名，不编造网址。

两份都带 `待整理` 状态和知识库约定的 frontmatter。整理过程中状态行显示「正在整理讲稿和笔记…」，长课约一两分钟。

没有配 DeepSeek KEY 时只存转写稿并提示；「生成笔记」按钮一直在，可以事后重跑（会再生成一份，不覆盖旧的）。

## 右下角的表情球

用了开源项目 [sam70361/aora-bot](https://github.com/sam70361/aora-bot) 的 Emotion Ball（32 种表情，纯 SVG + 原生 JS，零依赖）。文件在 `emotion-ball/js/`，没有构建步骤。

固定悬浮在右下角，`z-index: 8`——在转写卡、指标条之上，在设置/笔记弹层之下。

**点一下球**可以暂停/恢复「跟着语气变」：暂停后球变半透明、停在待机，但录音中、整理中、出错这些工作状态照常显示。键盘 Tab 也能聚焦，回车同样生效。

它由三段信息驱动：

| 场景 | emotionId |
|---|---|
| 没开始 / 刚结束 | `02` 待机放空 |
| 正在录音 | `16` 专注 |
| 每段语气（😮😮🤔😌🙂😴） | `13` 惊讶 / `11` 疑惑 / `19` 满意 / `02` 待机 / `00` 睡眠 |
| 识别卡住、降级存盘 | `32` 处理中忙碌 |
| 补识别 | `40` 检索资料 |
| 整理笔记 | `30` 思考中 → `33` 任务完成 |
| 任何接口报错 | `34` 出错 |

> 授权：引擎与表情配置对个人使用免费，**球形角色的视觉形象禁止商用**，商用需要另行授权。自己用没问题，别拿去卖。

## 语气表情

每段音频切下来时顺手算一遍音量包络，不等识别结果就先判断语气。

**正文里只在语气明显时留一个表情**（😮 强调 / 🤔 疑问 / 😌 收尾），平静的句子不加——满屏表情会变成噪音。三个判据：

| 表情 | 判据 |
|---|---|
| 😮 | 音量 95 分位达到平均的 2.8 倍，且持续 60ms 以上 |
| 🤔 | 尾段比开头高 30% 以上——尾音往上走 |
| 😌 | 尾段比开头低 40% 以下——音量往回收 |

**所有段落（含平静的）都会驱动右下角的表情球**，所以球是连续的，正文是稀疏的。

## 翻译

转写记录右上角三档：

| 档位 | 行为 |
|---|---|
| 原文 | 只显示识别结果（默认） |
| 自动 | 按每段的主要语言自动决定方向：中文段译成英文，英文段译成中文；纯公式/数字不译 |
| 中 → 英 | 每段识别完译成英文，灰字显示在这段下面 |
| 英 → 中 | 反过来 |

- 中途切档**只从切换那一刻往后译**，不回头补旧内容——回头补会把队列堵死，新字幕反而迟迟不译。
- 想补前面的，点「补译前面 N 段」；它排在队尾慢慢跑，实时片段永远插队优先。
- 切回「原文」不会丢掉已译内容，再切回来同一方向直接复用，不重复请求。
- 翻译是逐段串行请求，一段约 1 秒，不会堵住识别。
- 译文会一起写进 `sessions/` 的转写稿（每段下面一行 `↳ 译文`），复制按钮也带译文。
- 用的是同一个 DeepSeek KEY，模型是设置里那个 `deepseek-flash`。

## 拍板书

左侧栏「拍板书」打开一块可拖动的小窗，对着投影幕或黑板按快门，截图会跟着这节课走。

```
① 点左侧栏「拍板书」→ 右下角出现小窗（拖标题栏可以挪位置，位置会记住）
② 点「打开摄像头」→ 浏览器会问一次摄像头权限
③ 按「按快门」→ 存一张，右上角计数 +1
④ 录完点「结束并保存」→ 生成笔记时按时间插到对应章节
```

**截图存哪**

```
D:\知识库\attachments\课堂截图-2026-10-29-2150-01m35s.jpg
```

文件名里带 `01m35s`，就是这个画面在课上的时间点。可以在 `config.json` 里改目录：

```json
"shot_dir": "attachments",     // 相对知识库根目录；留空则存 sessions/shots/
"shot_link_style": "wiki"      // wiki → ![[文件名]]；md → ![](attachments/文件名)
```

**怎么插进笔记**

截图按「最后一个起始时间不晚于它的章节」归位，插在那章末尾，并带一行标注：

```markdown
![[课堂截图-2026-10-29-2150-01m35s.jpg]]
> 截图 01:35
```

没有时间章节的笔记，统一放到文末 `## 课堂截图`。

**几点说明**

- 摄像头是**独占**的，开会软件占着时会提示「被别的程序占用」，关掉那边再点「打开摄像头」。
- 画面只在本机保存，**不会**发给 DeepSeek 或硅基流动。
- 截图会以原文比例存成 JPEG（最长边 1600px，约 100–200 KB 一张）。
- 保存转写稿时会在 `sessions/` 里写一份同名 `.shots.json` 清单，所以「重新整理」不会丢图。
- 导出 Word / PDF / HTML 时图片会一起带走（HTML 用 base64 内嵌，单文件可分享）。

## 工作方式

```
麦克风 → PCM 切片(16kHz 单声道 WAV) → 本地服务 → 识别接口 → 字幕
                                              ↘ 翻译接口 → 译文（可选）
                                                         ↓
                                    结束存稿 sessions/*.md
                                                         ↓
                「生成笔记」→ DeepSeek → 完整讲稿 + 结构化笔记 → Obsidian
```

不是流式 WebSocket，是「分段伪实时」：每 6 秒送一段，延迟约 1–3 秒。好处是任何 OpenAI 兼容接口都能接；要真正逐字上屏需要各家的流式协议，可以再加适配器。

笔记分两份产出：**完整讲稿**（去掉语气词、合并重复、按逻辑重排成通顺文本）和**结构化笔记**（主题 → 章节 → 重点提示 → 课后任务 → 自测题）。模板写在 `server.py` 的 `NOTE_PROMPT` 里，可以自己改。

## 笔记落在哪

生成完的笔记直接写进 **Obsidian 收件箱**：`D:\Obsidian\00-收件箱\`（路径可在设置里改）。

文件名：`课堂笔记-<标题>-2026-10-24-0945.md`，**同名不覆盖**，重复写会自动加 `-2`。

frontmatter 按知识库 `AGENTS.md` 的约定：

```yaml
---
created: 2026-10-24 09:45
updated: 2026-10-24 09:45
tags:
  - 待分类
  - 课堂笔记
source: 课堂实时转写
kind: 笔记
status: 待整理
---
```

`.kb/kb_sync.py` 每 30 分钟扫一次收件箱：会把它转存成 `02-笔记` 下的正式笔记、原件进 `99-归档`、写一条日记。这是你库里原本的设计，不是这个工具加的。

如果想**跳过收件箱流程**，直接把「笔记落盘位置」改成 `D:\Obsidian\02-笔记` 即可；留空则只存本地 `sessions/`。

> 注意：`00-收件箱` 里的文件名若以 `_` 开头，`kb_sync` 会跳过不处理（它自己的忽略规则）。
